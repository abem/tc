## 2. 査による根本原因の独立確認（優先対応のため、投資先の判断材料として先行共有）

`venv-nemotron-poc/lib/python3.12/site-packages/transformers/models/nemotron3_5_asr/processing_nemotron3_5_asr.py`（実際にpipインストールされたソース）を直接読んだ結果:

```python
def __call__(self, ..., language: str | list[str] = "auto", ...):
    ...
    inputs["prompt_ids"] = self._resolve_prompt_ids(language, len(audio))

def _resolve_prompt_ids(self, language, batch_size):
    if isinstance(language, str):
        language = [language] * batch_size
    if len(language) != batch_size:   # ← language=None だとここで TypeError
        raise ValueError(...)
```

`DEFAULT_PROMPT_DICTIONARY`に`"auto": 101`が実在する（L181実測）。すなわち**Nemotronは`language="auto"`という文字列そのものを渡すことに正式対応している**（`__call__`のデフォルト値自体が文字列`"auto"`）。`language=None`を渡すと`isinstance(None, str)`が`False`のためリスト化されず、直後の`len(None)`で今回の本番エラー（`TypeError: object of type 'NoneType' has no len()`）と完全に一致する例外が発生することを、実際のソースコードで確認した。

**結論**: 本指示書§4項目2の(a)/(b)の判断は、**(a)（対応している）で確定できる**。`scripts/nemotron_infer.py` L56の`language_arg = None if args.language == "auto" else args.language`が誤りであり、`"auto"`を`None`へ変換せず**そのまま文字列として渡す**（実質的にはこの変換処理自体を削除し`language_arg = args.language`とする）のが正しい修正方向である。本指示書はこの判断を「作の調査結果に委ねる」形で(a)/(b)両方を提示しているが、査が先行して一次資料（実際にインストールされた本番相当バージョンのソース）で確定させたため、作は(a)の裏取りに要する時間を短縮できる（(b)の設計変更は不要になる可能性が高い）。**この確認事実は査読合格の条件ではなく、参考情報として共有する**（作業指示書自体の記載に誤りはなく、差し戻しの対象ではない）。
