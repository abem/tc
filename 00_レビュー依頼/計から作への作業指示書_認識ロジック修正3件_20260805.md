## 4. 成果物の仕様・要件

### 4-1. 項目1（優先度: 高）: context注入の幻覚リスク是正

**背景**: `core/transcription_interface.py` の `_transcribe_long_audio()`（L673-801、`context` 引数は
L719・L740で全チャンクに一律注入）で、全チャンクに対して同一の `context` 文字列を渡している。
無音・不明瞭なチャンクの冒頭で、ヒント語彙が「発話された」と誤認される幻覚（存在しない発話の
でっち上げ）の直接原因となっている。

**予備調査で技術検討・決定すること**（いずれか、または他案の提示可。決定は計へ報告し承認を得る）:
- (a) `context` の注入を最初のチャンク（`i == 0`）のみに限定する
- (b) Qwen3-ASRへ渡すプロンプト構成を「発話リストではなくヒントである」とモデルが誤認しにくい形へ
  変更する（例: プレフィックス文言の追加等。ただし `Qwen3ASREngine.transcribe()`/`_model.transcribe()`
  のAPI仕様上、`context` 引数の意味論を変えられる範囲を予備調査で確認すること）

**検討観点**（予備調査で報告すること）:
- 各案の副作用（例: (a)採用時、2チャンク目以降で固有名詞ヒントが効かなくなることの許容性）
- 既存の反復ループ検出・再試行ロジック（L728-753相当）や失敗チャンクプレースホルダ挿入への影響有無
- 実際に幻覚が抑制されることを検証する方法（サンプル音声での再現・比較が可能か）

**要件**:
- `Qwen3ASREngine.transcribe()`（L604・L610、単一チャンク処理のelse分岐）は本チケットの対象外
  （`_transcribe_long_audio()` のみが対象。単一チャンクの場合はチャンク分割自体が発生しないため
  今回の幻覚リスクの対象外）。
- ポストプロセッサ（LLM後処理）方式へのアーキテクチャ移行は**スコープ外**（今回は対象外、
  実施しないこと）。

### 4-2. 項目2: エントリーポイント間の機能不整合解消

`transcribe.py` の `TranscriptionConfig(...)` 構築箇所（`process_with_progress()` 内、L166-172、
`settings["device"] = resolve_device(...)` の直後）に `context=` の配線が無い。`./tc`
（`transcribe_audio()` L59相当）は `load_context_hints(whisper_config.get("context_file", "config/context_hints.txt"))`
で読み込み配線しているが、`transcribe.py` は同じ設定ファイル（`config/config.yaml`）を使っていても
この配線が無いため、起動方法によって認識精度が変わる状態になっている。

**実装要件**:
1. `transcribe.py` の import 群に `from core.utils import load_context_hints` を追加する
   （現状未import）。
2. `TranscriptionConfig(...)` 構築箇所（`process_with_progress()`）で、`tc` と同型に
   `UnifiedConfig.get("whisper", "context_file", default="config/context_hints.txt")` を
   `load_context_hints()` へ渡し、`context=` として `TranscriptionConfig` へ配線する。
3. `UnifiedConfig` は `transcribe.py` に既にimport済み（`run()` 内で `UnifiedConfig.load(...)` 実行済み）
   のため、追加importは不要（`load_context_hints` のみ追加）。

### 4-3. 項目3（軽微）: config.yamlのdead codeクリーンアップ

`config/config.yaml` の `whisper.language_models` セクション（`ja`/`en` の `default`/`alternatives`
を持つブロック。設定ファイル内のコメントで「`core/cli_common.py:select_model()` は現在どこからも
呼ばれていない(dead code)」と自己申告済み）を削除する。

**実装要件**:
1. `whisper.language_models` セクション全体（コメント行含む）を削除する。
2. `core/cli_common.py` の `select_model()` 関数自体は**本チケットの対象外**（削除しない。
   `config.yaml` セクションのみを削除する）。
3. `language_models` を参照する他の記述（ドキュメント等）が無いか `grep -rn "language_models"` で
   確認し、あれば完了報告に列挙する（削除は本文書のスコープ次第で計に確認。config.yaml以外は
   基本的に対象外）。
