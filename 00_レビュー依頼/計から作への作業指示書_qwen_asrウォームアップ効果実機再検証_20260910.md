## 2. 背景と目的

tc-ops #441（systemdサービス再起動直後の初回文字起こしが `No module named 'qwen_asr'` で失敗する事象）は、根本原因が未確定のまま一度クローズ（診断チケット、commit 9478a6a）され、並行してウォームアップ暫定緩和策（`@st.cache_resource` 付き `_warmup_qwen_asr()`、commit e6712f9）のみ実装・dev反映済み。

采による2026-09-10実態確認（Redmine #441 journal #3332）により、緩和策導入後に「実機で症状が実際に解消しているか」の再検証が未実施であることが判明した。本指示書はこの再検証のみを対象とする。

## 3. ゴール（完了条件）

以下の手順を最低3回（試行回数はsaku技術判断で増減可、ただし3回未満は不可）ループし、全回で `OK_NO_ERROR` が出力されること（1回でも `FAIL_REPRODUCED` が出た場合は「未解消」と判定）。

```bash
# 各試行:
# 本機はJST(UTC+9、timedatectlで確認)。journalctl --sinceはローカル時刻として解釈するため、
# --sinceに渡すタイムスタンプもローカル時刻で生成する(dateに-uを付けない。
# commit 9478a6aの既存診断と同方式に統一)。
RESTART_TS=$(date +"%Y-%m-%d %H:%M:%S")
systemctl --user restart tc-webui.service
sleep 5   # サービス起動待ち(実機で調整)
# ここでWebUI経由で文字起こしジョブを1件投入する(UI操作のため機械化不可、手動実施と明記する)
sleep 15  # ジョブ完了待ち(実機で調整)

MATCH_COUNT=$(journalctl --user -u tc-webui.service --since "$RESTART_TS" \
  | grep -c "No module named 'qwen_asr'")

if [ "$MATCH_COUNT" -eq 0 ]; then
  echo OK_NO_ERROR
else
  # 二段確認: 非0件時、該当行が検査コマンド自身の出力でないことを目視確認する
  journalctl --user -u tc-webui.service --since "$RESTART_TS" | grep "No module named 'qwen_asr'"
  echo FAIL_REPRODUCED
fi
```

- タイムゾーン注意（査sa再査読指摘、2026-09-10是正）: `date -u`（UTC）で生成した時刻を`journalctl --since`（ローカル時刻解釈）へ渡すと本機（JST、UTC+9）では約9時間の時間窓ずれが生じ判定精度が保証されない。上記のとおり`date`（ローカル時刻、`-u`なし）に統一した。実行前に`timedatectl`でタイムゾーンを再確認すること。
- 上記手順のうち「WebUI経由でのジョブ投入」はブラウザ操作のため機械化不可。完了報告に投入した入力（URL等）・投入時刻を明記すること。
- 全試行で `OK_NO_ERROR` → 「解消」と判定。1回でも `FAIL_REPRODUCED` → 「未解消」と判定し、原因未解明のまま継続する。
