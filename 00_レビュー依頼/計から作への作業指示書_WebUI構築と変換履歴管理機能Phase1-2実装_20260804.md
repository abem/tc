## 4. 成果物の仕様・要件

### 4-1. Phase1: 変換履歴DB実装

設計書（変換履歴DB設計_20260806.md）に基づき実装する。特に以下を厳守する:

1. `core/cli_workflow.py` に `record_transcription_history()` を新規追加（設計書§5-2のシグネチャ準拠）。
   `UnifiedTranscriber.transcribe()` 自体は変更しない。
2. `transcribe.py` の `save_results()`（L205-236）から `record_transcription_history()` を呼び出す。
   **査sa指摘の是正済み設計を厳守**: GDriveアップロードの `try` ブロックへ入る前
   （L216相当、`console.print(f"ローカル保存先: {output_file}")` の直後）に
   `full_url: Optional[str] = None` を初期化すること（`source_type=="local"` での
   `UnboundLocalError` を防止する設計。設計書§5-2是正内容と完全一致させる）。
3. 記録処理は独立の `try/except` で囲み、失敗時は `console.print` で警告表示のみとし、
   `process_with_progress()` の例外伝播（既存のGDriveアップロード失敗時と同様の扱い）に含めない
   （既存CLIワークフローへの無影響要件、設計書§6）。
4. DDL（設計書§3）どおりに `transcription_history` テーブルを作成する初期化処理を実装する
   （テーブル未作成時は自動作成、`CREATE TABLE IF NOT EXISTS`）。

### 4-2. Phase2: WebUIプロトタイプ実装

設計書（WebUIフレームワーク選定とプロトタイプ方針_20260806.md）に基づき、Streamlitで実装する。

1. 主要画面5点（入力フォーム／設定パネル／リアルタイム進捗表示／テキスト・SRTプレビュー／履歴一覧）
   を設計書§3の記載どおりに実装する。
2. `context_hints` 入力欄は設計書§4のとおり、デフォルト非表示（`st.expander`）・警告文常時表示・
   使用前の同意チェックボックスを実装する。
3. 5分チャンク処理の非同期実行は設計書§5のとおり、`threading.Thread` + `queue.Queue` +
   `st.fragment(run_every="1s")` で実装する。
4. `core/` の既存関数（`UnifiedTranscriber.transcribe()`、`resolve_input_audio()`、
   `upload_transcription_result()`）は変更せず、新規ラッパー層（配置・命名は saku 裁量、
   完了報告に明記）から呼び出す構成とする（設計書§6のクラス抽象化方針）。
5. SRTプレビュー（§3-4）は「タイムスタンプ付与オン」時のみ表示する設計どおりに実装する
   （新設する整形関数の配置先ファイル名は saku が決定し、完了報告に明記する。査読時の
   宿題事項として先送りされていた点）。

### 4-4. `./tc`（推奨実行エントリーポイント）への統合（追加スコープ、2026-08-04追記）

**経緯**: saku予備調査で判明。CLAUDE.md記載の推奨実行方法 `./tc`（ルート直下、拡張子なし）は
`transcribe.py` とコードを共有しない独立した `main()` を持ち（`transcribe_audio()`/`save_result()`
独自実装、L48/L92/L135）、承認済み設計・当初指示書は `transcribe.py` の `save_results()` のみを
対象としていたため、**`./tc` 経由の実行では変換履歴が一切記録されない**状態だった
（推奨エントリーポイントが対象外では方針書2章の目的に反する）。計の判断により統合対象に追加する。

**実装要件**（`./tc` の実測: L135 `def main():` 〜 L208、`try/finally` 構造、L171-196相当）:

1. `upload_url` のスコープ問題（transcribe.py で査sa指摘済みと同型のバグを事前に回避する）:
   `upload_url` は `if resolution.source_type in {"youtube", "gdrive"} and not args.no_upload:`
   （L177相当）の内側でのみ代入される。`source_type=="local"` または `--no-upload` 指定時は
   未代入のままとなるため、この分岐へ入る**前**（L173相当、`transcribed_text = result.text` の直後、
   `output_path = save_result(...)` の前後いずれか）で `upload_url: Optional[str] = None` を
   初期化すること。
2. `record_transcription_history()` の呼び出しをGDriveアップロードブロック終了後（L190相当、
   `print("アップロードに失敗しました")` の後）に追加する。独立の `try/except` で囲み、
   失敗時は `print()` で警告表示のみとし、`main()` の実行（`finally` 節での一時ファイル削除処理を含む）
   をブロックしない設計とする（`transcribe.py` と同一の無影響方針）。
3. `record_transcription_history()` 自体（`core/cli_workflow.py`）は共通実装を再利用し、`./tc` 専用の
   別実装を作らない。呼び出し元（`transcribe.py` / `./tc`）ごとに引数（`result`/`resolution`/
   `output_file`/`settings` 相当/`gdrive_url`）を揃えて渡す。
