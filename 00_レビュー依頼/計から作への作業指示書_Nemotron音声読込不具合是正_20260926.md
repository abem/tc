## 2. 背景と目的

采是正指示（優先、2026-09-26T14:21:30Z、sai→kei）により、Phase2実装のNemotron機能に本番不具合が判明した。ユーザーがWebUIでNemotronを選んで変換したところ、以下のエラーで失敗した:

```
文字起こしに失敗しました: Nemotronサブプロセスが異常終了しました(code=1):
Loading model: nvidia/nemotron-3.5-asr-streaming-0.6b
Model loaded in 26.24s
ERROR: TypeError: object of type 'NoneType' has no len()
```

**原因の切り分け（采・計で更新済み、2026-09-26T14:23:33Z）**: ユーザーが同じDriveファイルで言語を「ja」に指定したところ変換に成功した。失敗するのは「自動判定」選択時のみ。したがって当初の仮説（`load_audio()`がNoneを返した）は誤りの可能性が高く撤回する。**有力な仮説**: WebUIの既定言語「自動判定」→`config.language`が`None`→`_resolve_language`が`'auto'`を返す→`nemotron_infer.py`が`language_arg=None`で`processor(..., language=None)`を呼び出し、processor内部で`len(None)`相当の処理に当たっている。**WebUIの言語選択の既定値は「自動判定」であるため、このままでは初回操作で必ず失敗する（重大度高）。**

なお、当初仮説だった音声読み込み手段の違い（`transformers.audio_utils.load_audio()` vs 既存エンジンの`librosa`/`soundfile`）自体は、今回の失敗の直接原因ではない可能性が高いが、入力形式の多様性（Google Drive/YouTube由来ファイルは元形式のまま渡される、`core/cli_workflow.py`の`resolve_input_audio`、L31-実測）に対する検証不足は事実であり、采指示により非wav入力の回帰テストは予防的に残す。

**あわせて対応する軽微事項（采指摘、計の判断）**: 隔離venv名`venv-nemotron-poc`は、本番コード経路（`core/nemotron_engine.py`）から呼ばれる以上「PoC」の名が実態と合わない。本指示書で`venv-nemotron`へ改名する。

## 4. 成果物の仕様・要件

1. **原因の確定（最優先、GPU不要）**: `scripts/nemotron_infer.py`の`except Exception as e:`節に`traceback.print_exc(file=sys.stderr)`を追加する（`_log()`によるメッセージ出力は維持）。采提供の再現用Google Driveファイル（下記§6）をダウンロードし、言語引数を`auto`（＝`language=None`）にした場合のトレースバックを確認し、`TypeError: object of type 'NoneType' has no len()`が采の仮説（`processor(..., language=None)`内部での`len(None)`相当の処理）と一致するかを確定させる。**この確認は音声読み込み部分のみで完結する場合はGPU不要だが、`processor()`呼び出しの内部まで追う場合はモデルロードが絡む可能性がある。モデルロード（GPU使用）が必要になった時点で作業を止め、計経由で采へ連絡すること（着手前ではなく、必要になった時点でよい。采条件④）。**
2. **Nemotronの言語自動判定対応可否の調査**: HuggingFaceモデルカード・`transformers`の`Nemotron3_5AsrProcessor`実装（隔離venvにインストール済みの`transformers==5.17.0`のソースを直接読むこと）を確認し、以下いずれかを判定する:
   - **(a) 対応している場合**: 正しい引数の指定方法（例: `language="auto"`という文字列そのものを渡す、または引数を渡さない等）を確認し、`scripts/nemotron_infer.py`の呼び出しを修正する。
   - **(b) 対応していない場合**: 下記3の方針で対応する。
3. **(b)の場合の対応方針（計の判断）**: `webui.py`の言語選択（L117実測、`options=["自動判定", "ja", "en"]`）について、Nemotron選択時は「自動判定」を選べないようにし、既定値を`ja`へ切り替える。実装は`include_timestamps`の既存パターン（Phase2実装、`webui.py`のNemotron選択時に値を強制上書きする設計）に倣うこと: 選択肢からの除外（`disabled`や`options`の動的変更）に加え、`language_choice`の値自体も強制的に`"ja"`とし、Streamlitのウィジェット状態残留（Phase2実装で発覚した`include_timestamps`と同種の不具合）が起きないようにすること。あわせて`nemotron_engine.py`の`_resolve_language()`（L70-76実測）にも、`"auto"`が渡された場合の防御的なフォールバック（例: `"ja-JP"`にフォールバックしつつログに警告を出す）を追加し、WebUI以外の呼び出し経路（将来のCLI対応等）でも同じ失敗が起きないようにする。
4. **隔離venvの改名**: `venv-nemotron-poc` → `venv-nemotron`。対象: `scripts/setup_nemotron_venv.sh`（内部の`VENV_DIR`等）、`core/nemotron_engine.py`（パス参照箇所）、`scripts/nemotron_infer.py`（docstring中の使用例）。既存の`venv-nemotron-poc/`ディレクトリは`.gitignore`の`venv*/`パターンで新旧いずれの名前もカバーされるため`.gitignore`自体の変更は不要（実測して確認すること）。物理ディレクトリの改名・再構築は本指示書のスコープ外（GPU実測時に新規構築される）でよいが、コード・スクリプト上の参照はすべて新名に統一すること。
5. **回帰テスト追加**:
   - **必須**: Nemotron選択時に言語「自動判定」を選んでもクラッシュしない（またはそもそも選べない）ことを検証する回帰テスト（`webui.py`の設定パネル、または`_resolve_language()`の単体テスト。GPU不要）。
   - **予防的（采指示④、必須ではないが実施）**: 非wav形式（mp3またはm4a）の音声ファイルを用いた音声読み込みの動作確認。`transformers.audio_utils.load_audio()`が采提供の再現用ファイル（実際の形式）で正常に動作するかを診断し、問題があれば追加の是正要否を完了報告に記載する（今回の失敗の直接原因ではない可能性が高いため、問題がなければ「診断済み・問題なし」の記録のみでよい）。
6. **デバイス指定の無視バグ是正（采追加指摘、2026-09-26T14:30:29Z、本是正に含める旨は計の判断）**: `scripts/nemotron_infer.py` L47は`device_map="auto"`に固定されており、`core/nemotron_engine.py`はサブプロセスへデバイス指定を一切渡していない。実運用比較（変換履歴#70: device=cpu指定で327秒音声を33.2秒処理、#71: GPU実行で19.5秒。cpu指定時の処理時間がGPU実行と同水準であり、cpu指定が無視されている疑いが濃厚）を踏まえ、以下を実施する:
   - `NemotronSubprocessEngine.transcribe()`から`scripts/nemotron_infer.py`呼び出しに`--device`引数（`self.config.device`由来、既存エンジンと同じ値域: `auto`/`cuda`/`cpu`）を追加する。
   - `nemotron_infer.py`側で`--device`引数を受け取り、`cpu`が指定された場合は`device_map="auto"`ではなく明示的にCPU上でモデルをロードする（例: `device_map=None`かつ`.to("cpu")`、または`device_map={"": "cpu"}`等、`transformers`の実装に即した確実な方法を採用すること）。
   - **回帰テスト（必須、GPU不要）**: `--device cpu`指定時に、実際にCPU上でロードされること（GPUメモリを使用しないこと）をテストで保証する。モデルの実ロードを伴わない場合は、`nemotron_infer.py`に渡される`device_map`引数の値を検証する単体テストでも可（モックで代替する場合はその設計を完了報告に明記すること）。
