## 2. 背景と目的

ユーザー承認済み。話者分離機能は実際には一度も動作していない死んだ機能であることが采調査・
計の独自検証（両者一致）で判明した。

**計が独自検証した事実**:
- `core/transcription_interface.py` `_initialize_diarization()`（L946-951）:
  ```python
  def _initialize_diarization(self):
      """Initialize speaker diarization if enabled."""
      try:
          from core.diarization_engine import DiarizationEngine
          self.diarization_engine = DiarizationEngine(self.diarization_config)
      except ImportError:
          self.logger.warning("Diarization dependencies not available")
  ```
  `core.diarization_engine`モジュールはリポジトリに存在せず、`git log --all --diff-filter=A --
  '*diarization_engine*'`でも一度も存在した形跡がない。`ImportError`は握りつぶされ
  `self.diarization_engine`が`None`のまま処理が続行するため、WebUIの「話者分離を有効化」
  チェックボックスをONにしても文字起こし結果に一切反映されない（エラー表示も無い）。
- `speaker_diarization.py`（リポジトリルート）: `pyannote.audio`を使う独立した実装
  （`SpeakerDiarizer`/`SpeakerAwareTranscriber`）が存在するが、`webui.py`・`transcribe.py`・
  `tc`・`core/*`・`tests/*`のいずれからも一切参照されていない単体スクリプト
  （`grep -rn "speaker_diarization\|SpeakerDiarizer\|SpeakerAwareTranscriber"`で自己参照のみ確認）。
  依存の`pyannote.audio`自体も`pyproject.toml`/`uv.lock`に記載なし（未インストール）。
- `DiarizationConfig`（`core/config.py` L122-140）は**死んだコードではなく複数箇所で実際に
  使用されている**（`webui.py` L37,208-209、`transcribe.py` L27,180-183,187、
  `core/transcription_interface.py` L21,928,1095、`core/config.py` L173,191,238、
  `core/__init__.py` L9,65、`tests/test_core_config.py` L55-70）。ただし、その先の
  `_initialize_diarization()`が常にImportErrorで無効化されるため、**設定を渡しても効果が無い**
  という構造。

**重要（混同禁止）**: タイムスタンプ機能（`ForcedAligner`、`core/transcription_interface.py`
L478-782、`qwen_asr.inference.qwen3_forced_aligner.Qwen3ForcedAligner`を使用、テスト11件
通過・正常動作確認済み）は話者分離とは完全に別のコードパスであり、**本チケットの対象外**。
削除・変更してはならない。

## 4. 成果物の仕様・要件

### 4-1. 予備調査で確認・判断すること（実装着手前に計へ報告、承認を得る）

**明確に撤去すること（采指示・計検証済み）**:
1. `webui.py`の「話者分離を有効化」チェックボックス（現状 L119付近）およびそれに連動する
   `settings["diarization"]`・`DiarizationConfig(...)`生成箇所（L208-209付近）
2. `core/transcription_interface.py`の`_initialize_diarization()`（L946-951）等、存在しない
   `core.diarization_engine`を参照する死んだコード経路

**予備調査で影響範囲を確認し、削除/存置を判断すること**（CLAUDE.md「大量のファイルを一括削除
する前に使用状況を確認すべし」原則に従う）:
3. `DiarizationConfig`（`core/config.py`）・`UnifiedConfig`内の関連フィールド・
   `tests/test_core_config.py`の`TestDiarizationConfig`
4. `config/config.yaml`の`speaker_diarization`セクション（L94-105）
5. `transcribe.py`側の話者分離関連の参照（CLIプロンプト・`--diarization/-d`フラグ、
   L64,68,81,133,139,142,180-183,187,276,320-321付近）
6. `speaker_diarization.py`（未使用単体スクリプト、リポジトリルート）

**検討観点**（予備調査で報告すること）:
- 3-6を完全削除する場合、`UnifiedTranscriber`のコンストラクタシグネチャ
  （`diarization_config`引数）自体をどう扱うか（引数削除は`webui.py`/`transcribe.py`双方への
  影響があるため、削除の順序・一貫性に注意）
- 将来的に話者分離を実装し直す可能性を考慮し、設定スキーマ（`DiarizationConfig`・
  `config.yaml`セクション）を「未実装機能のプレースホルダ」として残す選択肢もありうるか
  （**独断で判断せず、両論を計へ提示すること**。過去の教訓「M-046: 計の独断回避」に倣い、
  saku単独で「削除が正解」と決め打ちしない）
- `speaker_diarization.py`は`pyannote.audio`という未インストール依存を要求するため、残す場合も
  「動作しないスクリプト」であることが明確になるよう扱う（例: ファイル冒頭に注記を残す等）
