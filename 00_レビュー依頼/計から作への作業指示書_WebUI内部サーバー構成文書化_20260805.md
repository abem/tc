動いているか』を推測せず読めるようにする」こと。**実装（コード）の変更は一切含まない、
文書のみの追加タスク。**

## 4. 成果物の仕様・要件

`docs/system-docs/webui_architecture.md`（新規、既存の `system_overview_2025.md` 等と同階層）に、
以下6項目を記載する。**采による調査済みの事実として提供されているが、日数経過・環境差異により
陳腐化しうるため、執筆前に実機で再確認し、確認できた実測値で記載すること（確認せず転記しない）**:

1. **サーバースタック**: `streamlit`（バージョンは実機で `uv pip show streamlit` 等により再確認）は
   内部的に Starlette（ASGIフレームワーク、`streamlit/web/server/starlette/starlette_app.py`）を
   uvicorn（ASGIサーバー）で起動している。tornadoの導入有無も実機で再確認する
   （旧バージョンStreamlitはTornadoベースだったため、混同防止の注記として記載）。
2. **起動コマンドと起動ログ**: `uv run streamlit run webui.py` 相当の起動コマンド、および起動時ログの
   代表例（usage statistics収集の案内、`--server.headless` 指定時のブラウザ自動起動抑制等）を実機実行して採取する。
3. **バインド・公開URL**: 起動ログに表示される Local URL・Network URL・External URL の3種の意味を説明し、
   **デフォルトでは全インターフェースにバインドされ、認証機構が無いため外部公開時にはリスクがある旨を
   セキュリティ上の注意事項として明記する**（本要件は必須、省略不可）。
4. **WSL2固有の挙動**: ファイル変更監視がpoll方式にフォールバックする旨のログ・挙動を実機で再確認し記載する。
5. **通信方式**: ブラウザ・サーバー間はWebSocketで状態同期する実行モデル（スクリプト全体再実行+差分配信）。
   `webui.py` 側の `@st.fragment(run_every="1s")` による進捗表示部分のみのポーリング的再描画について、
   既存設計書（`00_レビュー依頼/作から計への設計書_WebUIフレームワーク選定とプロトタイプ方針_20260806.md`§5）
   の該当箇所を参照・引用する。
6. **起動/停止・ログ確認の正式な手順**: 開発時にどのように起動・停止・ログ確認を行うか、具体的なコマンド例
   （例: バックグラウンド起動、プロセス停止方法、ログ出力先の確認方法）を手順として記載する。
