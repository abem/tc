## 4. 成果物の仕様・要件

`docs/system-docs/webui_architecture.md` の末尾（既存の「6. 起動/停止・ログ確認の正式な手順」の後）に
新規セクション「7. systemdによる常駐化・自動起動」を追記する。**采提供の事実を実機で再確認し
（実際に `systemctl --user status tc-webui.service` 等を実行して確認できた内容で記載すること）**、
以下を含める:

1. **サービスファイル**: `~/.config/systemd/user/tc-webui.service` の内容（采提供の内容を実機で
   `cat`して再確認）。**このファイル自体はリポジトリ管理対象外**（ホーム直下の `~/.config/` 配下）で
   ある旨を明記する。
2. **有効化コマンド**: `systemctl --user daemon-reload && systemctl --user enable --now tc-webui.service`。
3. **ログイン無しでの自動起動**: `loginctl enable-linger abem` について、これはユーザーアカウント単位の
   システム設定でありリポジトリのコード変更ではない旨を明記する。
4. **運用コマンド**: status確認（`systemctl --user status tc-webui.service`）、再起動
   （`systemctl --user restart tc-webui.service`）、停止（`systemctl --user stop tc-webui.service`）、
   ログ確認（`journalctl --user -u tc-webui.service -f`）を実機実行して動作確認の上、記載する。
5. **他ホストでの再現手順として記載する**（本文書の性質上、「環境固有の設定であり、他ホストで同様に
   構築する場合の手順」という位置づけを明記すること。特定ユーザー名`abem`等の環境固有値は
   プレースホルダ化するか、環境固有の実例である旨を注記する。既存文書（§3節）のIPアドレス
   プレースホルダ化と同じ配慮）。
6. 既存の「6. 起動/停止・ログ確認の正式な手順」（開発時のフォアグラウンド/バックグラウンド起動）との
   関係を明確にする（systemd常駐化は本番相当の運用方法であり、6節の手動起動とは別の運用モードである旨）。
