## 3. 実機確認（tc-ops #440是正3等で用いた再現手順の再実施）

「正常なYouTube URL（時間を要する）を投入した400ms後に、無効なURL（即座に失敗する）を投入する」
という、網羅調査（パターン1b）で表示順の問題を確認した手順を、is正後のコードに対して別ポート
（8502）の検証用インスタンスで再実施しました。

**実測結果**（サーバーログ・スクリーンショット添付）:
```
#1（jNQXAC9IVRw）: 投入時刻21:28:36 / 確定時刻21:28:51（時間を要して後から確定）
#2（invalid00000）: 投入時刻21:28:37 / 確定時刻21:28:38（即座に失敗、先に確定）
```
表示順は **`[完了] #1 ...(確定 21:28:51)` が上、`[失敗] #2 ...(確定 21:28:38)` が下**となり、
投入は#1が先・#2が後にもかかわらず、**実際に最後に確定した#1が一番上**に表示されることを
確認しました（真の新しい順、is正前は逆でした）。各`st.expander`を展開すると本文冒頭に
「投入順: N件目 / 投入時刻: HH:MM:SS / 確定時刻: HH:MM:SS」が表示され、投入順と確定順の関係が
一目で読み取れることも確認しました（添付スクリーンショット）。

見出しに`#item_id`が常時表示されるため、同一URLを複数回投入した場合の識別不能問題（網羅調査
パターン1・5）も併せて解消されています（見出し自体に一意な番号が入るため）。
