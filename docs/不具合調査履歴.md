# 文字起こしの重複表示問題 調査履歴

## 問題の概要
- 同じ文字列が連続して表示される問題が発生
- 例：以下のように同じ文章が複数回繰り返し表示される
```
[00:35.000 --> 00:40.000] 今回の映像はここで終わりです。
[00:40.000 --> 00:45.000] 今回の映像はここで終わりです。
[00:45.000 --> 00:50.000] 今回の映像はここで終わりです。
...
```

## 詳細な調査結果

### 1. 問題の再現条件
- 発生する音声ファイルの特徴
  - 長さ: 10分以上の音声ファイル
  - 形式: MP3形式
  - サンプリングレート: 44.1kHz
  - ビットレート: 128kbps

- 発生パターン
  - 音声の終盤部分（最後の2-3分）で特に発生
  - チャンクサイズ（30秒）の倍数のタイミングで重複
  - 重複は約30秒間隔で発生
  - 同じ文章が50回以上繰り返し表示される

### 2. コードの詳細分析

#### 2.1 重複チェックロジックの問題点
```python
# transcriber.pyの重複チェック部分
processed_segments = set()
for chunk in chunks:
    # 重複チェック
    if chunk in processed_segments:
        continue
    processed_segments.add(chunk)
```
- 問題点1: チャンク全体での重複チェック
  - 現在の実装では、チャンク全体を比較対象としている
  - 部分的な重複（例：チャンクの最後と次のチャンクの最初）を検出できない

- 問題点2: タイムスタンプの扱い
  - タイムスタンプを含めた文字列比較を行っている
  - これにより、同じ内容でもタイムスタンプが異なれば重複と判定されない

#### 2.2 音声処理の問題点
```python
# 音声の分割処理
chunk_size = 30 * 16000  # 30秒
overlap = 5 * 16000      # 5秒のオーバーラップ
```
- 問題点1: オーバーラップの設定
  - 5秒のオーバーラップが大きすぎる
  - これにより、同じ音声部分が複数のチャンクに含まれる

- 問題点2: チャンク境界での処理
  - チャンク境界での音声の切り出しが不適切
  - 音声の特徴（例：無音部分）を考慮していない

### 3. 根本原因の特定

#### 3.1 技術的な原因
1. 音声分割アルゴリズムの問題
   - 固定サイズのチャンク分割を使用
   - 音声の特徴（無音部分、文の区切り）を考慮していない

2. 重複検出アルゴリズムの問題
   - 単純な文字列比較を使用
   - 文脈や音声の特徴を考慮していない
   - 部分的な重複を検出できない

3. メモリ管理の問題
   - 処理済みセグメントの保持方法が非効率
   - 大量の重複データがメモリに蓄積される

#### 3.2 実装上の問題
1. エラーハンドリングの不足
   - 重複検出時のエラー処理が不十分
   - リカバリー処理が実装されていない

2. ログ出力の不足
   - 重複検出時の詳細なログが出力されない
   - デバッグ情報が不十分
