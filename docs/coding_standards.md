# コーディング規約

## 【最終警告】作業開始前の必須チェックと手順

### 1. デグレ対応に12時間を浪費した事実を肝に銘じろ
- 履歴破壊・テスト未実行による大事故を二度と起こすな
- 過去の事故を教訓として、徹底した予防を心がけよ

### 2. 規約全文の完全熟読と理解宣言
- `coding_standards.md` を冒頭から末尾まで「完全に」熟読すること
- PR冒頭に "既読・理解済み" と明記すること
- 未記載のPRは即時差し戻し
- 以降、指摘なしで作業を進めることを許さない

### 3. Git操作の厳格な制限
- 一切の force‐push/Rebase/Reset を禁止
- ブランチ切り替え・マージ時のコンフリクトは自力解決厳禁
- コンフリクト発生時は即リードに報告

### 4. テストの神聖視
- コード変更前に必ず `pytest` をフル実行
- 全テストが **緑になるまで** 絶対にコミット／プッシュしない
- テスト失敗時のコミットは即時差し戻し

### 5. ドキュメントとの完全同期
- 仕様変更・バグ修正のたびに以下を更新：
  - README
  - `coding_standards.md`
  - 関連するコメント
- ドキュメント未更新のPRは却下

### 6. CIの必須設定と有効化
- 以下の自動チェックを必ず設定・有効化：
  - テスト通過確認
  - ドキュメント更新確認
  - 履歴改変チェック
- 自動チェックが失敗した場合は即時作業停止

### ⚠️ 違反時の措置
- これらの手順を守れない者は**直ちに作業権限を停止**
- 責任者の許可なく再開を認めない
- 再発防止こそ最優先事項である

## 2. コーディングスタイル

### 2.1 命名規則
- クラス名: UpperCamelCase
- 関数名・変数名: snake_case
- 定数: UPPER_SNAKE_CASE
- プライベート変数・関数: _leading_underscore

### 2.2 インデント・スペース
- インデント: 4スペース
- 行の最大長: 120文字
- 関数間: 2行空ける

## 1. 認証関連の取り扱い

### 1.1 Google Drive API認証
- `credentials.json`と`token.pickle`は必ず`.gitignore`に含める
- 認証ファイルのバックアップは別の安全な場所に保管する
- 認証ファイルの更新時は以下の手順を必ず実行する：
  1. 既存の認証ファイルのバックアップを作成
  2. 新しい認証ファイルを配置
  3. 動作確認
  4. バックアップを安全な場所に移動

### 1.2 認証ファイルの更新手順
```bash
# 1. バックアップの作成
cp credentials.json credentials.json.backup
cp token.pickle token.pickle.backup

# 2. 新しい認証ファイルの配置
# credentials.jsonを新しいものに置き換え

# 3. 動作確認
python transcribe_audio.py "テスト用のGoogle Drive URL" --output-format txt

# 4. バックアップの移動
mv credentials.json.backup /path/to/secure/backup/
mv token.pickle.backup /path/to/secure/backup/
```

### 1.3 認証関連のトラブルシューティング
- 認証エラーが発生した場合：
  1. バックアップから認証ファイルを復元
  2. 認証ファイルの権限を確認（600）
  3. 必要に応じて認証を再実行

## 11. ファイル管理

### 11.1 文字起こしファイルの管理
- 文字起こしファイルは `output/transcriptions/` ディレクトリに保存
- ファイル名のフォーマット: `YYYYMMDD_HHMM_transcription.txt`
- 古いファイルは `output/transcriptions/archive/` に移動
- 一時ファイルは `output/transcriptions/temp/` に保存
- 定期的なクリーンアップを実施（30日以上経過したファイル）

### 11.2 ファイル命名規則
- 日時ベース: `YYYYMMDD_HHMM_transcription.txt`
- ソースベース: `transcription_[FILE_ID].txt`
- バージョン管理: `transcription_[FILE_ID]_v[VERSION].txt`

### 11.3 クリーンアップ手順
```bash
# 1. 古いファイルのアーカイブ
find output/transcriptions -name "*.txt" -mtime +30 -exec mv {} output/transcriptions/archive/ \;

# 2. 一時ファイルの削除
rm -f output/transcriptions/temp/*.txt

# 3. 空ディレクトリの削除
find output/transcriptions -type d -empty -delete
```

### 11.4 バックアップ
- 重要な文字起こしファイルは定期的にバックアップ
- バックアップは `output/transcriptions/backup/` に保存
- バックアップの命名規則: `backup_YYYYMMDD_HHMM.tar.gz`
