## 1. 予備調査結果（4-1節）

### 1-1. 採用する実装方式

**(b)案（`@st.cache_resource`）を採用する**。

**(a)案（モジュールトップレベルimport）との比較**: 両案とも、実行タイミング自体は「最初の
セッション接続でスクリプトが初回execされるとき」であり実質的に同じ（Streamlitはサーバー起動時
ではなく最初のブラウザ接続時にスクリプト全体を初回execする実行モデルのため）。相違点は
以下のとおりで、(b)を優位と判断する:
- (a)はスクリプト再実行（rerun）のたびにトップレベルの`import qwen_asr`文が構文上は毎回
  評価されるが、`sys.modules`キャッシュにより2回目以降は実質ノーコスト（この点は明記のみで
  問題にはならない）。ただし**失敗時の例外処理をトップレベルに書くと可読性・保守性が落ちる**
  （`main()`等の呼び出し側から見えにくい）。
- (b)は`@st.cache_resource`により「プロセス全体で一度だけ実行・結果をキャッシュ」という意図を
  コードで明示でき、複数ブラウザセッションから呼ばれても再実行されないことが保証される
  （Streamlit公式のプロセス単位シングルトンパターン）。例外処理を関数内にカプセル化でき、
  戻り値でウォームアップ成否を追跡できる。

### 1-2. 「実際のユーザーの初回リクエストより前」の担保についての報告（重要な限定事項）

Streamlitの実行モデル上、**HTTPリクエストを一切受けていない状態でアプリケーションコードを
実行することはできない**（サーバープロセス起動直後、誰もアクセスしていない間はスクリプト自体が
実行されない）。したがって本ウォームアップが担保するのは「サーバー起動から完全に独立した事前
実行」ではなく、**「最初のブラウザアクセス（ページロード）時点で実行され、ユーザーが実際に
文字起こしボタンを押すより確実に先行する」**という意味での前倒しである。ページロードから
ユーザーが入力・設定を行いボタンを押すまでには通常数秒以上を要するため、実用上はtc-ops #441の
症状回避（緩和）に資すると考えるが、**この限定を完了報告・査読時に明記する**（指示書文言の
解釈をここで確定させ、後日の誤解を防ぐ）。

### 1-3. ウォームアップ失敗時の扱い

`try/except Exception`で捕捉し、`logger.warning(...)`のみ出力してWebUI起動（スクリプト実行）は
継続する。**例外を再raiseしない**（要件どおり、WebUI起動自体を失敗させない）。戻り値
（`bool`）でウォームアップ成否を保持するが、UI上にエラー表示は行わない（ウォームアップは
あくまで裏側の前倒し処理であり、失敗時も既存の遅延import（`_load_model()`側、無変更）が
通常どおり動作し続けるため、ユーザーへの追加通知は不要と判断する）。

### 1-4. 既存の起動シーケンスとの実行順序

`main()`冒頭、既存の`_load_config()`（L55-61）の直後に`_warmup_qwen_asr()`を呼ぶ。設定読み込みと
同様「起動時に一度だけ行う前処理」という位置づけで揃える。

## 2. 実装計画

### 2-1. 対象ファイル

`webui.py`のみ。新規関数`_warmup_qwen_asr()`（`@st.cache_resource`デコレータ付き）を追加し、
`main()`冒頭で呼び出す。

```python
@st.cache_resource
def _warmup_qwen_asr() -> bool:
    """WebUIプロセス起動時にqwen_asrパッケージのimportを一度だけ先行実行する
    (tc-ops #441関連の暫定緩和策)。モデル重み本体のロードは行わない(import文のみ)。
    st.cache_resourceによりプロセス単位でキャッシュされ、複数セッションから呼ばれても
    1回のみ実行される。importに失敗してもWebUI起動自体は継続する(警告ログのみ)。"""
    try:
        import qwen_asr  # noqa: F401
        logger.info("qwen_asrウォームアップ成功")
        return True
    except Exception as e:
        logger.warning("qwen_asrウォームアップ失敗(起動は継続): %s", e)
        return False
```

`core/transcription_interface.py`の`Qwen3ASREngine._load_model()`（既存の遅延import）は無変更
（4-2節どおり、モデル重みロードは対象外、根本原因調査とも独立）。
