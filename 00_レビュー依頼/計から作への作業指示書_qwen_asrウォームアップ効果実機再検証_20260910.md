## 2. 背景と目的

tc-ops #441（systemdサービス再起動直後の初回文字起こしが `No module named 'qwen_asr'` で失敗する事象）は、根本原因が未確定のまま一度クローズ（診断チケット、commit 9478a6a）され、並行してウォームアップ暫定緩和策（`@st.cache_resource` 付き `_warmup_qwen_asr()`、commit e6712f9）のみ実装・dev反映済み。

采による2026-09-10実態確認（Redmine #441 journal #3332）により、緩和策導入後に「実機で症状が実際に解消しているか」の再検証が未実施であることが判明した。本指示書はこの再検証のみを対象とする。

## 3. ゴール（完了条件）

以下を機械検査コマンド相当の手順で記述する。

- `systemctl --user restart tc-webui.service` を実行し、再起動直後にWebUI経由で文字起こしジョブを投入した際、`Qwen3ASREngine - ERROR - Transcription failed: No module named 'qwen_asr'` がサーバーログ（`journalctl --user -u tc-webui.service` 等）に一切出力されないことを確認する（試行N回、Nはsaku技術判断で決定するが最低3回とし、全回で非出力であること）。
- 上記いずれかの試行で当該エラーが再現した場合は「解消していない」と判定し、原因未解明のまま継続する。
