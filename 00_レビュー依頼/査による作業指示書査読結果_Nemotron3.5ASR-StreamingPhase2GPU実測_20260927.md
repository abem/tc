## 2. 是正必須（不合格の根拠）: チャンク処理が未実装のまま「実測検証」対象としている

本指示書§3・§4項目4は「Phase2設計report §5で暫定採用したCHUNK_THRESHOLD_SEC=300の妥当性を、10-20分規模の音声で検証する」としているが、**この文言は「チャンク処理の仕組みが既に実装済みで、閾値の妥当性だけを実測で確認する」という前提に立っている。しかし実際にはチャンク処理は一切実装されていない**。

```
$ grep -n "CHUNK\|chunk" core/nemotron_engine.py scripts/nemotron_infer.py
(該当なし)
```

Phase2設計report§5は「チャンク処理は要」と判断し対策案（300秒単位で分割・複数回サブプロセス呼び出し・結果連結）を提示したが、Phase2実装work order（commit fbca18a）の成果物一覧（§4項目1-7）にはこの実装が含まれておらず、緊急是正（commit e48756b）にも含まれていない。現在の`NemotronSubprocessEngine.transcribe()`は、音声の長さに関わらず**常に1回のサブプロセス呼び出しで全体を処理する**実装のままである。

**このまま10〜20分規模の音声でGPU実測を行うと、VRAM不足でクラッシュする可能性が高い。** 査がPhase1実測値（既に検査で一致確認済みの一次データ）から線形外挿で再計算した結果:

```
load_diff平均: 2414MiB（候補2: 2137MiB、候補3: 2690MiB）
推論時追加分の増加率: 16.51 MiB/秒（候補2・候補3の2点から算出）
現在のベースラインVRAM: 5300MiB（jev-local停止後、采実測）

10分(600秒): 推論時追加分推定 9957MiB → ピーク推定 17671MiB（総VRAM16376MiBを1295MiB超過）
15分(900秒): 推論時追加分推定14909MiB → ピーク推定 22623MiB（6247MiB超過）
20分(1200秒): 推論時追加分推定19861MiB → ピーク推定27574MiB（11198MiB超過）
```

**指示書が指定する「10-20分」の範囲は、下限（10分）でさえ総VRAM容量を超過する推定値になる。** チャンク処理を実装しないままこの規模の音声を投入すると、GPU実測の貴重な機会（jev-local停止・ユーザー待機中）をクラッシュで消費する可能性が高い。

**是正指示**: §4に、チャンク処理の実装（`NemotronSubprocessEngine`または`scripts/nemotron_infer.py`側で、`CHUNK_THRESHOLD_SEC`超過時に音声を分割し複数回サブプロセスを呼び出して結果を連結する設計。Phase2設計report§5の対策案に基づく）を、**GPU実測着手前の成果物として明記**されたい。実装はGPU不要（ロジックのみ）であり、その後のGPU実測（E2E確認・長尺音声実測）で実際に機能することを確認する、という順序にすべきである。
