## 2. 背景と目的

ユーザーが実機でWebUI（`webui.py`）を使用したところ、YouTube等からダウンロードした音声一時ファイルが
`output/` に残留するバグが発見された（実例: 220MBのwavファイル）。

**原因（采調査・計にて実測確認済み）**: `transcribe.py`（L201-202）・`tc`（L159-167、L221-223）は
処理完了後に `resolution.is_temp_file` または `resolution.source_type == "gdrive"` の場合、
`cleanup_temp_file()` または `os.remove()` で一時ファイルを削除している。`webui.py` の
`_save_and_record()`（L168-201）にはこの削除処理が移植されておらず、WebUI経由の変換では
一時ファイルが削除されずに残り続ける。

**設計上の追加留意点（査sa指摘・是正済み）**: `tc` のクリーンアップは `try/finally`（L218〜L224相当）
により**成功・失敗いずれの経路でも必ず実行される**。一方 `webui.py` の `_render_progress_and_result()`
（L204-230）は `job.error is not None` の分岐（L223-225）で `_save_and_record()` を呼ばずに
`return` する制御フローになっている。クリーンアップを `_save_and_record()` 内にのみ配置すると、
**文字起こし失敗時は一時ファイルが是正後も残留し続ける**（tcの「必ず削除される」という本質的性質が
再現されない）。このため、クリーンアップ処理は共通関数へ切り出し、成功パス（`_save_and_record()`）・
失敗パス（`job.error is not None` 分岐）の両方から呼び出す設計とする（4節参照）。

## 4. 成果物の仕様・要件

**共通クリーンアップ関数を新設し、成功パス（`_save_and_record()`）・失敗パス
（`_render_progress_and_result()` の `job.error is not None` 分岐、L223-225相当）の両方から呼び出す**
（2節の追加留意点参照。`tc` の `try/finally` が持つ「成功・失敗いずれの経路でも必ず削除される」性質を
再現するため）。

```python
def _cleanup_temp_file(resolution: InputResolution) -> None:
    """ダウンロードした一時音声ファイルを削除する（成功・失敗いずれの経路でも呼び出す）。
    ローカルアップロードファイルは削除しない（tc/transcribe.pyの既存挙動と整合）。"""
    needs_cleanup = resolution.is_temp_file or resolution.source_type == "gdrive"
    if not needs_cleanup:
        return
    try:
        if os.path.exists(resolution.local_audio_path):
            if resolution.youtube_handler:
                resolution.youtube_handler.cleanup_temp_file(resolution.local_audio_path)
            else:
                os.remove(resolution.local_audio_path)
    except Exception as e:
        st.warning(f"一時ファイルの削除に失敗しました: {e}")
```

**要件**:
1. `resolution.is_temp_file`（YouTube等）または `resolution.source_type == "gdrive"` の場合のみ削除する
   （`tc` の `needs_cleanup` 判定と同型。`InputResolution` は `gdrive` の場合 `is_temp_file=False` かつ
   `youtube_handler=None` で返るため、`os.remove()` フォールバックが必要）。
2. **ローカルアップロードファイル（`source_type == "local"`、`is_temp_file == False`）は削除対象外とする**
   （ユーザーが明示的にアップロードしたファイルであり、CLI側（`transcribe.py`/`tc`）の挙動とも整合させる。
   采指示の明示要件）。
3. `webui.py` の先頭 import 群（L15-17付近）に `import os` を追加する（現状未import）。
4. `_cleanup_temp_file()` の呼び出し箇所は2つ:
   - `_save_and_record()`（L168-201）の末尾（L201の後、`record_transcription_history()` 呼び出しの後）。
   - `_render_progress_and_result()` の `job.error is not None` 分岐（L223-225相当、`return` の前）。
     この分岐では `_save_and_record()` が呼ばれないため `resolution` を `st.session_state["job_resolution"]`
     から取得する必要がある（`None` の可能性を考慮し、取得できた場合のみ呼び出す）。
5. `_cleanup_temp_file()` 自体が例外を発生させても呼び出し元の関数全体を失敗させない設計とする
   （関数内部で独立 `try/except` を持ち、削除失敗時は `st.warning()` で警告表示のみとする）。
6. `os.path.exists()` チェックにより、`st.fragment(run_every="1s")` による再実行で同一ジョブに対して
   複数回呼び出されても、2回目以降は何もしない（安全に冪等）ことを確認する。
