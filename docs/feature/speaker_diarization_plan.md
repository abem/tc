# 話者選別（話者分離/ダイアリゼーション）機能追加計画書

## 1. 背景・目的
- 会議・対談・インタビュー等の音声データにおいて、話者ごとに発言区間を分離し、文字起こし結果に「誰が話したか」を明示することで、可読性・分析性を大幅に向上させる。
- 既存の文字起こしパイプライン（Whisperベース）に「話者分離」機能を統合し、エンドユーザーにとって実用的な話者ラベル付きテキスト出力を実現する。

## 2. 現状の課題
- pyannote.audio v2系はPython 3.10/torch 1.13環境でしか安定動作しない。
- v3系はAPIが大幅変更されており、既存コードとの互換性がない。
- 長時間音声・多人数会話での精度・速度・リソース消費のバランスが課題。
- Whisperの文字起こしと話者分離の「区間対応」ロジックが煩雑化しやすい。
- **現状は依存競合・環境制約のため話者分離機能は一時停止し、「高精度文字起こし＋句読点付与」のみで安定運用中。**

## 3. 目標
- pyannote.audio（v2系 or v3系）による話者分離とWhisper文字起こしの連携パイプラインを構築
- 出力形式：話者ラベル＋発話区間＋テキスト（例：SRT, VTT, JSON, TXT）
- ローカルGPU/CPUで完結、pip installで再現可能な環境
- エラー時の堅牢な例外処理・リソース管理

## 4. 技術選定・推奨アーキテクチャ
- **話者分離**：pyannote.audio（v2.1.1 + torch 1.13 + Python 3.10）推奨
    - v3系対応も検討（API調査・サンプル実装）
- **文字起こし**：transformers + kotoba-whisper等の日本語特化モデル
- **区間連携**：pyannoteで得た各話者区間ごとに音声を切り出し、Whisperで逐次推論
- **設定管理**：config.yamlで全パラメータ一元管理
- **出力**：話者ラベル付きテキスト（SRT, VTT, JSON, TXT）

## 5. 実装・テスト・運用フロー
1. **環境構築**
    - Python 3.10仮想環境作成、torch/pyannote.audio等のバージョン固定
2. **話者分離パイプライン実装**
    - pyannote.audio Pipelineで話者区間抽出
    - 区間ごとに音声を切り出し、一時ファイル管理
3. **Whisper連携**
    - 各区間ごとにtransformersベースWhisperで文字起こし
    - 区間・話者ラベル・テキストを統合
4. **出力整形・保存**
    - SRT/VTT/JSON/TXT等のフォーマットで保存
5. **テスト**
    - サンプル音声で精度・速度・リソース消費を検証
    - エラー・例外・リトライ・リソースリークの有無を確認
6. **運用・ドキュメント整備**
    - README/セットアップ手順/トラブルシューティングの更新

## 6. リスク・注意点
- pyannote.audio v2系はPython 3.11以降非対応、v3系はAPI互換性に注意
- 長時間・多人数音声での精度低下・リソース消費増大
- HuggingFaceトークン・Google認証情報等の機密管理
- 一時ファイル・GPUメモリのクリーンアップ徹底

## 7. 今後の展望
- v3系pyannote.audioへの移行検証
- 独自話者辞書・話者名推定の導入
- Web UIやAPI化によるユーザビリティ向上
- **現状は「話者分離なし・高精度文字起こし＋句読点付与」で安定運用中。話者分離は今後の拡張計画として位置付ける。**
