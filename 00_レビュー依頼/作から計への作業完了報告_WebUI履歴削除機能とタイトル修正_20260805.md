## 3. 実機操作による削除UXの確認（指示書3節、機械検査になじまない要件）

**本番ファイルを削除操作対象にしない検証手順**（査sa差し戻し対応）: `DEFAULT_HISTORY_DB_PATH`が
`Path("output/history.db")`固定であるため、以下の手順で本番ファイル自体を一切の削除操作対象に
せずに検証しました。

```bash
# 1. 事前バックアップ(通常の作業安全手順として)
cp output/history.db backup/20260805_133830/history_backup_before_verification.db

# 2. 本番ファイルを一時退避(rename、これ以降DEFAULT_HISTORY_DB_PATHの位置には存在しない)
mv output/history.db output/history.db.prod_original_20260805_133830

# 3. 退避した本番ファイルの複製を、検証用としてDEFAULT_HISTORY_DB_PATHの位置に配置
#    (以降の削除操作は全てこの複製に対してのみ行われる、本番ファイルはこの時点で無関係)
cp output/history.db.prod_original_20260805_133830 output/history.db

# 4. 複製へダミーレコード(2026-05-01、既存全件は2026-08-05のため無関係)を1件挿入して検証実施
# 5. (検証後)複製を破棄し、退避しておいた本番ファイルを復元
rm output/history.db
mv output/history.db.prod_original_20260805_133830 output/history.db
```

Streamlit実サーバー + Playwrightで、上記手順3で配置した**複製**に対し、履歴タブ→「古い履歴の
一括削除」展開→操作を実施:

1. **展開直後（無警告即時削除でないことの確認）**: 「①対象件数を確認」ボタンのみ表示され、
   削除ボタンは存在しない（添付①）。
2. **①クリック後（削除対象件数の事前表示）**: 「2026-07-06より前の履歴が1件あります(削除対象は
   データベースの記録のみで、output/配下のファイルやGoogle Drive上のファイルは削除されません)。」
   と表示され、「②1件を削除する」ボタンが出現。この時点でダミーレコードはまだDB上に存在すること
   をページ本文の実測テキストで確認済み（＝①だけでは削除されない）。（添付②）
3. **②クリック後（実削除・完了表示）**: 「1件の履歴を削除しました。」と表示（添付③）。

**検証後の整合性確認**（手順5の復元後に実施）: 複製DBの総件数は削除前後で11件（ダミー挿入で
12件→削除で11件に復帰）を確認した上で複製を破棄。復元後の`output/history.db`（本番ファイル）は
`SELECT COUNT(*)`で11件、内容は退避前と完全に同一であることを実測確認済みです。**本番ファイルは
検証の全過程を通じて一度も削除操作の対象になっていません**（手順2で退避された時点から手順5で
復元されるまでの間、`DEFAULT_HISTORY_DB_PATH`が指す実体は常に複製でした）。
