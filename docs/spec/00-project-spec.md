# プロジェクト仕様（利用者に見える挙動の正本）

tc-ops #566 / #567 Phase 5 の Task 5.0 で新設。複数の実装に分かれていた挙動を 1 つに決め、
実装（`tc`、`transcribe.py`、`webui.py`、`core/`）はこの文書に従う。

決定日は D1〜D8 が 2026-10-03(D2 の一部は 10-02)、D9〜D11 が 2026-10-04。D1〜D3 はユーザー回答（Plans.md「決定事項」。D1・D3 の内容は Plans.md を参照）、
D4〜D6 はユーザーが Phase 5 の実行を承認（2026-10-03「Phase 5 に進んで」）したうえで、
作が現状の実装を調べて採用した。異論があれば本文書を直し、実装を合わせる。

## 決定一覧

| ID | 決めること | 決定 | 決定日 |
|----|-----------|------|--------|
| D2 | 正とする CLI | `tc` と `transcribe.py` を両方残し、共通処理（`core/`）に寄せる。廃止しない。bash の `transcribe` は `transcribe.py` を仮想環境で呼ぶだけの薄いラッパーなので現状のまま残す | 2026-10-02（ユーザー）／`transcribe` の扱いは 2026-10-03 |
| D4 | 保存形式 | タイムスタンプ付与が有効で、整合に成功した場合（`result.metadata["timestamps_included"]` が真かつ `result.segments` がある）だけ、各セグメントの先頭に `[MM:SS] ` を付けて 1 セグメント 1 行で保存する。それ以外は `result.text` をそのまま保存する。`tc`・`transcribe.py`・`webui.py` のすべてで同じにする | 2026-10-03 |
| D5 | 一時ファイルの削除対象 | 処理の終了時（成功・失敗・中断のいずれでも）に、次を削除する。yt-dlp が作った音声（YouTube・X）、Google Drive からダウンロードした音声（実体は一時ファイル）。ローカルファイルの入力は削除しない。削除に失敗しても処理結果は失敗にしない（警告のみ） | 2026-10-03 |
| D6 | yt-dlp が無いとき | 自動で `pip install` しない（uv 管理の `.venv` を書き換えない）。検出は 1 つの方法に揃え、見つからなければ、対処（`uv sync`）を書いたエラー（`YtDlpNotFoundError`、`ValueError` のサブクラス）で止める。検出順は PATH → 現在の Python と同じ `bin/` → `.venv/bin/yt-dlp`（`handlers/youtube.py` の `find_yt_dlp()`） | 2026-10-03 |
| D7 | WebUI のアップロードの保存と整理 | アップロードごとに一意なサブディレクトリ `output/uploads/<一意>/<ファイル名>` に保存し、同名でも上書きしない。ファイル名は区切り文字・制御文字を除いた単一の名前にし、最大 200 文字（超える分は拡張子を残して切り詰める。空・`.`・`..` は `upload`）とする。保存から 7 日を過ぎた項目（サブディレクトリ、およびそれ以前の平置きファイル）は、新しい投入のたびに削除する。処理待ち・処理中のジョブが使うファイルとシンボリックリンクは消さない。履歴 DB が記録した元ファイルのパスは、7 日後には存在しなくなる | 2026-10-03（ユーザー指示。保持日数は作が採用） |
| D8 | WebUI の URL 入力ダウンロード（`output/queue_downloads/<トークン>/`）の整理 | 処理後の音声は D5 で削除されるが、空のディレクトリや失敗時の部分ファイルが残るため、1 日を過ぎた項目を新しい投入のたびに削除する。処理待ち・処理中のジョブが使うファイルとシンボリックリンクは消さない | 2026-10-03（ユーザー指示。保持日数は作が採用） |
| D9 | 進捗表示 | WebUI は進捗バーを出す: ダウンロードの割合、Qwen3-ASR 長音声のチャンク進捗、Whisper の 30 秒チャンク進捗。経過時間と残り時間を併記するが、進捗が 3% 未満、または率が不明のときは残り時間を出さない。Nemotron と短い音声は経過時間のみ。CLI は進捗率つきの通知を 10% 刻みに間引いて表示する（`core/progress.py`） | 2026-10-04（実装済みの挙動を記録。実装の定数が正） |
| D10 | 外部由来の文字列の扱い | アップロード名・URL・エラー文・動画タイトルは、ログとキューのラベルで 1 行にする（制御文字は `\n`・`\x1b` のような見える形にエスケープ）。エラー文は 1000 文字までに切り詰める。アップロード名は D7 のとおり最大 200 文字で、区切り文字・制御文字を除き、空・`.`・`..` は `upload` にする（`core.utils.one_line`、`sanitize_upload_filename`） | 2026-10-04（実装済みの挙動を記録。実装の定数が正） |
| D11 | yt-dlp の取得 | 検出順は PATH → 現在の Python と同じ `bin/` → `.venv/bin/yt-dlp`（D6）。タイムアウトは、`--socket-timeout` 30 秒、メタデータ取得 60 秒、ダウンロード中は出力が 300 秒途絶えたら中断する | 2026-10-04（実装済みの挙動を記録。実装の定数が正） |

D9〜D11 は、実装済みの挙動を記録したもの。数値は実装の定数と一致し、`tests/test_docs_consistency.py` が一致を検査する。

## 当時の変更点（記録）

Phase 5（2026-10-03）の時点で、実装を決定に合わせたときの差分。現在はすべて実装済みで、現行の挙動は上の決定一覧が正。

|------|---------|--------|

## 変えないもの

- 出力ファイル名（`build_output_file()`）、Google Drive の保存先の決め方、履歴 DB のスキーマ（DDL・FTS トリガー）
- 反復検出の論理と閾値（実装に従う）、チャンク分割の閾値（Qwen3-ASR 300 秒、Nemotron 350 秒）
- `tc` の引数（`--dry-run` を含む）と終了コード
