## 2. 背景と目的

ユーザー要望（2026-08-05、tc-ops #440）に基づく。WebUI（`webui.py`）は現在、入力欄が1件のみで、
処理中は次の投入ができず待たされる。「入力してキューにためて次々処理してほしい」という要望を受け、
文字起こしジョブをキュー処理化する。

**現状の実装確認（計が実機コード再確認済み）**:
- `webui.py` の `_start_job()`（L136-166）が `st.session_state["job"]` へ `TranscriptionJob` を
  1つだけ保持する。`main()` 内の「実行」ボタン押下（L342-343）のたびに `_start_job()` が呼ばれ、
  実行中でも `st.session_state["job"]` が新しいジョブで上書きされる（実行中スレッド自体はdaemonで
  走り続けるが、UIからの参照を失い進捗表示・完了処理が追跡不能になる）。
- `core/webui_workflow.py` の `TranscriptionJob` / `start_transcription_job()` はジョブ1件の
  非同期実行と進捗queue（`progress_queue`、ジョブ内部の進捗メッセージ用）のみを提供する。
  複数ジョブを待機させる機構は存在しない。
- `_render_progress_and_result()`（`webui.py` L223、`@st.fragment(run_every="1s")`）が1秒毎に
  再実行され、`job.done` を検知した時点（L238以降）で `_save_and_record()` を呼び出す。
  次ジョブの自動起動をどこに差し込むかは、この完了検知直後が候補だが、Streamlitの
  「スクリプト全体再実行」実行モデル上の制約（`@st.fragment` の再実行範囲、`st.session_state` の
  スレッド安全性）を踏まえた設計は本節時点で未検証であり、4節の予備調査で確定させること。

## 4. 成果物の仕様・要件

### 4-1. 予備調査で技術検討・決定すること（実装着手前に計へ報告、承認を得る）

- **キューのデータ構造と保持場所**: Streamlitは操作のたびにスクリプト全体を再実行するため、
  キュー本体は `st.session_state` に保持する必要がある。一方、バックグラウンドスレッドから
  「現在ジョブ完了→次のジョブ開始」を安全に行う経路（`@st.fragment(run_every="1s")` の
  再実行タイミングで判定するのか、別のスレッド安全な機構を要するか）を検討し、採用方式と
  根拠を報告すること。
- **ジョブ状態遷移**: 待機中／処理中／完了／失敗の状態と、状態ごとに保持する情報
  （投入内容、開始・終了時刻、結果や失敗理由への参照）を設計すること。
- **既存の単一ジョブ処理経路との統合方針**: `_start_job()` / `_render_progress_and_result()` /
  `_save_and_record()`（`webui.py` L136-220）をキュー対応へどう改修するか（新規関数への
  分離か、既存関数の拡張か）を報告すること。
- **既存の一時ファイル削除処理（`_cleanup_temp_file()`、L169-182）への影響**: 複数ジョブが
  順次処理される際、各ジョブが自身の `InputResolution` を正しく参照し、他ジョブの一時ファイルを
  誤って削除しないことを設計上どう担保するか報告すること。

### 4-2. 要件（ユーザー要望3点、いずれも必須）

1. **複数件の連続投入**: 入力フォームから、既存ジョブが処理中であっても新規ジョブを追加投入できる
   （現行のように投入内容が上書き・消失しないこと）。
2. **自動連続処理**: 投入された項目はキューへ積まれ、現在処理中のジョブが完了次第、自動的に
   次のキュー項目の処理を開始する（同時並列実行は行わない。GPU/モデルが1インスタンスのみの
   制約のため、逐次処理が前提）。
3. **キュー状態の可視化**: 待機件数・現在処理中の対象・完了済み一覧をUI上に表示する。

### 4-3. 対象外（スコープ外、実施しないこと）

- 複数ジョブの並列実行（GPU/VRAM制約により対象外。本チケットでは逐次処理のみ実装する）
- `core/transcription_interface.py` 等、既存の文字起こしロジック自体の変更
- キューの永続化（プロセス再起動をまたぐジョブの保持。本チケットではプロセス生存中のみ対象）
