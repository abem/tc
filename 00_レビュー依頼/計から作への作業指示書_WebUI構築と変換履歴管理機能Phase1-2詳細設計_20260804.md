## 4. 成果物の仕様・要件

### 4-1. Phase1: 変換履歴DB設計書

**必須記載項目**:
1. データストア方式の選定（SQLite想定、代替案JSONLとの比較・選定理由）
2. テーブル定義（DDL、または同等の構造定義）
3. 記録対象フィールドの一覧: 処理日時、音源ソース、使用モデル・デバイス・実行パラメータ、
   文字数統計、処理時間、結果テキスト本体・ファイルパス（`output/` 内）
4. `core/transcription_interface.py` / `core/cli_workflow.py` との統合ポイント
   （どの処理完了時点でどの関数・メソッドから記録するか）
5. 既存CLIワークフローへの影響有無（無影響であることが望ましい旨、方針書3節参照）

### 4-2. Phase2: WebUIフレームワーク選定・プロトタイプ方針設計書

**必須記載項目**:
1. Streamlit / FastAPI+シンプルフロントエンドの比較（開発コスト・保守性・
   5分チャンク処理の非同期表示への適合性の観点）と選定案（最終選定は計裁定のため「推奨」として記載）
2. 主要画面構成: 入力フォーム（YouTube/GDrive URL・ローカルファイル）、設定パネル
   （モデル/デバイス/言語）、リアルタイム進捗表示、テキスト・SRTプレビュー、履歴一覧画面
3. `context_hints`（ヒント入力欄）のデフォルト無効化または警告表示の設計
   （幻覚リスク: `config/context_hints.txt.sample` 参照）
4. 5分チャンク分割処理の非同期・安定動作方式（Streamlit採用時は `st.fragment` /
   Threading等の検討を含む）
5. `core/` ロジックのクラス抽象化方針（CLI・WebUI双方から共用できる構成の見取り図）
